# Logic FSM — First Working Combat Loop

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the 7-state Logic FSM so a triggered encounter runs a complete combat loop — turns cycle by CT/PULSE, actors auto-attack the nearest living opponent, win/loss is detected and exploration resumes.

**Architecture:** A single `LogicFSM` node child of `CombatScene` drives all logic states. It is actor-agnostic — it never branches on player vs enemy, only emits signals and awaits responses. For this first loop, ActionSelect is stubbed: FSM auto-selects the first living opponent and emits `action_selected` after a short delay; this is replaced with real player input when the UI FSM is built. CT advances in TurnTracker (pure static utility); damage math lives in CombatCalculator (pure static utility).

**Why one script for the FSM:** Each state is ~5–10 lines. Splitting 7 tiny states into 7 child nodes would create 7 files with 3 lines each — more files to track, not more clarity. The LogicFSM stays one node with an enum. If a state grows complex later (e.g. `REACTION_SCAN` with tiered resolution), *then* we extract it.

**Logic FSM leads, UI FSM follows:**
The Logic FSM is the authority. It drives state and emits signals; other systems react. The UI FSM never tells the Logic FSM what to do — it only responds to requests.
- Logic FSM emits `please_select_action(actor)` → UI FSM (or stub) shows menus, gets input, emits `action_selected`
- Logic FSM emits `turn_started(actor)` → UI FSM updates portraits, highlights active character
- Logic FSM emits `combat_ended` → UI FSM shows victory/defeat screen, GameManager returns to exploration
Logic FSM never branches on "is this a player?" It is actor-agnostic. It asks, it awaits, it continues.

**Implementation Strategy — State by State:**
We build this one state at a time. Each state gets implemented, tested in-game, and reviewed before moving to the next. The order is:
1. `COMBAT_START` → `TURN_START`
2. `ACTION_SELECT` (stub)
3. `ACTION_EXECUTION`
4. `REACTION_SCAN` (stub)
5. `TURN_END` with win/loss check
6. `COMBAT_END`
7. Wire everything together and run a full encounter

This prevents building a tower of assumptions that all break at once.

**Tech Stack:** GDScript 4, Godot 4.6, existing `CombatCharacter`/`VitalsComponent`/`StatsComponent` infrastructure, `CombatEvents` autoload event bus.

- [ ] **Step 1: Create the file**

```gdscript
class_name CombatCalculator
## Pure utility. Takes combatants in, returns resolved values out. No state, no Node base.

## Basic physical attack using the GDD damage formula:
##   damage = Power × AtkPhys / (DefPhys + 10) × Random(0.85, 1.0)
## Power is fixed at 30 for the stub basic attack (no mnemonic yet).
static func base_attack(attacker: CombatCharacter, target: CombatCharacter) -> int:
	const POWER: int = 30
	var atk: float = attacker.stats.stat(CharacterStats.Stat.AtkPhys)
	var def: float = target.stats.stat(CharacterStats.Stat.DefPhys)
	var variance: float = randf_range(0.85, 1.0)
	var result := int(POWER * atk / (def + 10.0) * variance)
	return max(1, result)
```

## Task 7 — TurnTracker

**Files:**
- Create: `scripts/combat/TurnTracker.gd`

- [ ] **Step 1: Create the file**

```gdscript
class_name TurnTracker
## Pure utility for CT/PULSE turn management. No state, no Node base.
##
## CT advances by PULSE/100 each "tick". Ticks are virtual — we loop until
## someone reaches 1.0 rather than advancing one tick per frame.
## Overflow is preserved: a fast actor's head start on the next turn is real.

static func advance_to_next_turn(actors: Array) -> CombatCharacter:
	while true:
		for actor in actors:
			if actor.vitals.is_downed():
				continue
			
			var pulse: float = actor.stats.stat(CharacterStats.Stat.Pulse)
			var ct_gain: float = pulse / 100.0
			actor.vitals.cur_ct += ct_gain
		
		var ready_actor := _find_ready(actors)
		if ready_actor != null:
			return ready_actor
	
	return null  # unreachable — at least one living actor always exists when called

static func consume_ct(actor: CombatCharacter) -> void:
	actor.vitals.cur_ct -= 1.0
	Log.debug("CT consumed", actor.character_name, actor.vitals.cur_ct)

static func _find_ready(actors: Array) -> CombatCharacter:
	var best_actor: CombatCharacter = null
	var best_pulse: float = 0.0
	
	for actor in actors:
		if actor.vitals.cur_ct < 1.0:
			continue
		
		var actor_pulse: float = actor.stats.stat(CharacterStats.Stat.Pulse)
		
		if best_actor == null:
			best_actor = actor
			best_pulse = actor_pulse
		elif actor_pulse > best_pulse:
			best_actor = actor
			best_pulse = actor_pulse
	
	return best_actor
```

func _enter_action_execution() -> void:

func _check_combat_end() -> bool:
	var any_enemy_alive := false
	var any_player_alive := false
	
	for actor in _actors:
		if actor.vitals.is_downed():
			continue
		
		if actor.is_player_controlled:
			any_player_alive = true
		else:
			any_enemy_alive = true
	
	if not any_enemy_alive:
		_transition(State.COMBAT_END)
		return true
	
	if not any_player_alive:
		_transition(State.COMBAT_END)
		return true
	
	return false

	end_combat()
